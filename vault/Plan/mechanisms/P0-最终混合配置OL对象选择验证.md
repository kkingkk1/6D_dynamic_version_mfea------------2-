# P0-最终混合配置OL对象选择验证

所属主计划 [项目计划](../../01-Plan.md)。

## 目标与已确认条件

在最终混合配置 `[2,0,0,0,4,2]` 上，验证已排任务信息能否改善 OL 的更新对象选择。该配置由 EDA 和 GA 组成，原始 G2/G3 为 `FULL/FULL`，G4 按过程停滞在两个父算法间切换，G5 为 `PAIRWISE_GREEDY`。见[论文草稿](../../Writing/paper_draft.md)、[十六场景复现报告](../../Results/Reports/mfea-current-six-global-20261008.md)和[固定配置入口](../../../src/main/java/main/RunSingleHybridConfig.java)。

在基于提交 `7f9f4e1` 的隔离实验中保留六槽入口。三组取同一父算法对、G4、G5、`GREEDY` 插入策略与总评估预算。首轮固定实际种群规模和子集大小，检验排程信号。G4 按同一规则运行，后续实际调用轨迹随搜索状态变化。

## 三组对照

- **A 原配置。** 每次由 G4 调用的父算法全量更新种群。A 提供最终混合配置的全量参照。
- **B 独立掩码＋排名。** 每个获准执行的父算法按当前适应度选前 `k` 个个体，适应度相同按种群位置排序。
- **C 独立掩码＋排名＋已排任务信息。** 在当前快照先按 B 算出各整数调度收益层的更新名额。每层按排名优先选不同的已排任务 ID 集合，余量再按排名补齐。C 与 B 使用相同的 `k` 和分层名额规则。初始化评估时从解码结果保存任务集合，G5 接受候选后更新对应种群位置的集合。

主要比较 C 与 B。A 与子集组的差异同时包含更新数量和执行路径的变化，用于判断相对原配置的总体表现。

## 任务与验收

### ☑ 任务 1｜验证掩码和评估计数

- 在 `HybCec` 的 G4 路由之后接入可切换的选择模式，使用 `HybridLevelCalculator` 生成 OL 掩码。复用 `PlanUtils` 的解码结果和 `PopulationManager` 的评估及写回路径。见 [HybCec](../../../src/main/java/core/HybCec.java)、[HybridLevelCalculator](../../../src/main/java/core/calculator/HybridLevelCalculator.java)、[PlanUtils](../../../src/main/java/utils/PlanUtils.java)和 [PopulationManager](../../../src/main/java/core/manager/PopulationManager.java)。
- 用含同收益、不同已排任务集合的小样例，检查 C 能在相同名额下改变选择。还要检查 EDA 和 GA 各自实际评估了全部选中位置、G5 接受后签名对应正确位置，以及旧入口在相同输入下复现原掩码与结果。
- 在三组 JVM 显式设 `-Dhybcec.fastPathBatchSize=1`，采用偶数种群且 `k=N/2` 至少为 2。预检确认 B/C 避开只处理首个目标的 OA1 批量路径，并实际对 `k` 个目标各评估一次。计数或位置不符时先修正接入。

### ☑ 任务 2｜做单星配对初筛

- 选 `1000-10-0-0-12` 区域场景。本地数据与 seed 行齐全，历史同配置场景收益率均值约为 48.17%，用于选点。按现有初始化获得一次任务分配，取任务数最多的卫星，平局取较小卫星 ID。固定该卫星的任务集合，每个 seed 让三组从完全相同的初始种群开始。见[历史场景结果](../../Results/Evidence/paper-fullspeed-update-20261009/data.csv)。
- 冻结 `N=196`、`k=98`、单星搜索上限 `19600` 次实际评估。取最接近历史 `nPop=195` 的较大偶数，并沿用每个初始个体对应 100 次总评估的档位。初始化计入搜索预算。三组各做一次终局解码，剔除成像时长不足的观测后核验可行性，分别记录原始整数收益、核验后的合法收益和终局耗时。若任一组搜索评估数未对齐，先修正计数或停止条件。
- 使用 `native200042` 的 `perRun=0..4`。用 Hybrid 入口核对场景 basename、首末索引、逻辑 seed ID 及实际 seed。预期 `perRun=0` 对应 ID 10、`1138252824073986`，`perRun=4` 对应 ID 14、`1138252824073998`。同轮三组使用同一实际 seed，并把手动启动的 `[RunSeed]` 与配对运行命令核对。先完成首轮预检，再补余下四个 seed。见 [native200042 种子表](../../../scene-seeds-native200042.properties)。
- 在 C 的同一选择快照记录 B 与 C 的索引差异。每组记录合法调度整数收益、实际评估次数、EDA/GA 各自的评估次数和运行时间。记录提取任务集合的开销，以便判断额外计算是否抵消收益。

### ☑ 任务 3｜判断是否扩大验证

- 若 C 在真实场景中未改变所选对象，记录信号未触发。若 C 改变了选择，比较五个配对的 C−B 收益差与时间。检查父算法调用比例，解释 G4 随搜索状态变化的影响。
- 选中确有变化且收益呈正向信号时，再扩大验证。小样本用于决定是否继续。复核支持有效后，再考虑让运行时控制器接管 G2/G3、保留 G0/G1/G4/G5 形成 4D，以及测试动态更新数。
- 原始运行材料保留在隔离工作树的 `outputs/final-hybrid-ol-target-p0/`。本轮初筛完成，目标替换信号未触发。结果和决定见 [P0 简报](../../Results/Reports/final-hybrid-ol-target-p0.md)。
