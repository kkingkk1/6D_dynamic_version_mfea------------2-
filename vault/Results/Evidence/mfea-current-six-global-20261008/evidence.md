# MFEA 胜者补齐六全局与十六场景汇总

## 问题与范围

用户补充全局场景也有新增项。继续使用 `[2,0,0,0,4,2]`，每场景五个 seed，已有结果不重算。本轮现用六全局来自相邻论文结果项目的 `six-algorithms-six-global-scenes-20261006/data.csv`，按真实 basename 匹配，不沿用历史 ID 编号。

本轮复用四个全局的 20 条历史结果，只补两个新全局的十次运行。与上一轮已完成的十区域 50 条合并后，覆盖当前 16 个场景、80 个唯一场景/seed 单元。区域旧 `1000-20-0-0-12` 继续排除，新 `2000-20-0-0-12` 保留。

## 方法

- 历史全局为 `500-5-1-0-24`、`1000-10-1-12-24`、`2000-20-1-12-24`、`6000-60-1-12-18`。逐条核对旧 canonical CSV、完成记录、配置、预期/实际 seed、原始日志和精确 properties。
- 新补 `3000-30-1-12-20`、`4000-40-1-12-18`，各五次。入口 `main.RunSingleHybridConfig`，factor 2.5、coefficient 100、确定性模式、GREEDY、无 warmup，每 JVM 一个 seed。
- 原 `native200042` 表缺少两个新全局的行。本轮自定义表保留原行，新行沿用原全局 500/5 profile：`1146114331680284、1146114331680288、1146114331680292、1146114331680295、1146114331680296`。对应 donor 的原 native290002 seed ID 13、17、21、24、25；不把新增行声称为新场景的历史原生行。
- 正式只用 perRun 0–4，每场景五个不同实际 seed。槽 5–19 为 schema 别名。JVM 实际日志记录 `source=custom table=seed-table.properties`；原 seed 表未修改。
- 复用上一轮冻结 class 与同日已通过的五项入口测试，启动前核对 149 个 Java 源码哈希未变。实验结束后再串行编译并跑相同五项测试，通过后归档。
- 先手动运行 3000/30 的 perRun 0 与 4，核对实际 seed 全字段和批处理命令。两条计入正式结果，不重复预检。
- BelowNormal、最多四 JVM、每个 Xmx4g。抽查四个并发进程实际优先级并记录资源采样。单次 deadline 900 秒，整批 1800 秒；没有超时或重启。

## 验证与边界

- 六全局 30/30 条，十区域 50/50 条，合计 80/80 条唯一记录；16 个真实 basename，各恰好五个不同实际 seed，配置一致。全局第三段均为 1，区域第三段均为 0，没有 train 场景。
- 本轮十个不同 PID 全部退出码 0，已确认退出。逐次核对实际 seed、配置、任务数/卫星数、nRun、预算及精确 properties，错误日志为空。
- 新运行输入、Java 源码、冻结 classes、原表与 tuning、历史 CSV、全局清单、上一轮区域数据和 manifest 哈希保持；完整清单记录在本包 manifest。
- 前置五项测试复用同日上一轮已通过的报告，源码哈希未变；后置实际运行五项入口测试，零失败。没有宣称完整测试套件通过。
- 本轮新增十次，没有重算历史全局 20 条或区域 50 条。两轮合计新运行 35 次、历史复用 45 条。
- 历史与新增的实现状态、seed 行来源和计时环境不同。该表是结果库存，不用于同批配对显著性或公平速度比较。入口未导出完整调度，本轮未逐任务独立验算。
