# MFEA 胜者在当前十区域的五 seed 结果

## 问题与范围

用户要求把 MFEA 优化得到的配置运行到当前全部新区域场景，已有结果不重复计算。使用已采用的 `[2,0,0,0,4,2]`。当前十区域排除旧 `1000-20-0-0-12`，包含新 `2000-20-0-0-12`；清单来自相邻论文结果项目的 `fig8-ten-regional-20261006/data.csv`，其路径与 SHA256 已记录。

用户确认每场景沿用五个 seed。最终覆盖 10 个区域、50 个唯一场景/seed 单元；25 条历史复用，25 次新增。

## 方法

- 复用 500/5、1000/10、4000/40、8000/80、10000/100，各五条。逐条核对旧 canonical CSV、完成记录、配置、预期/实际 seed 和现存原始日志、精确 properties。旧场景编号不用于匹配。
- 补测 2000/10、2000/20、3000/20、5000/50、6000/60，各五次。入口为 `main.RunSingleHybridConfig`，配置显式传入；factor 2.5、coefficient 100，确定性模式、GREEDY，无 warmup，每个 JVM 只运行一个 seed。
- 原 `native200042` 表缺少五个新 basename。本轮实验表保留全部原行，新增行沿用原表 `500-5-0-0-24` 的五 seed profile：`1146972547739811、1146972547739815、1146972547739819、1146972547739822、1146972547739823`。对应 donor 的原 native290002 seed ID 为 13、17、21、24、25。新场景没有历史 native290002 行，不把这些新增映射声称为其原生行。
- 表的 5–19 槽重复上述五个值以满足完整 schema；正式只使用 `perRun=0..4`，逻辑 seed ID 10–14，每场景五个不同实际 seed。JVM 指定自定义表，实际 `[RunSeed] source=custom`。
- 先完成编译和五项现有入口测试，再冻结 `target/classes` 到本轮现场。最多四个独立 JVM，`-Xmx4g`、BelowNormal；运行中抽查实际优先级，并记录整机 CPU 采样。单次 deadline 900 秒，整批 3600 秒。
- `2000/10` 的 perRun 0 与 4 分别手动启动并回读实际 seed 全字段，与批处理命令生成规则核对。两次均计入正式结果，没有重复 preflight。

## 验证与边界

- 50 条唯一结果，每场景恰好五个不同实际 seed，配置均为 `[2,0,0,0,4,2]`。旧 `1000-20-0-0-12` 零条，全局场景零条。
- 新增 25 个不同 PID，25 个退出码均为 0，所有目标进程已退出。逐次核对实际 seed、配置、任务数/卫星数、`nRun=1`、预算及精确 properties，错误日志为空。
- 新运行输入、Java 源码、冻结 class 文件、原 seed 表、原 tuning、旧 canonical CSV 和场景清单的 SHA256 前后保持；完整清单见 manifest。历史输入快照不能从现有材料完整恢复，因此不把旧结果声称为在本轮输入快照上重跑验证过。
- 实验前后各五项既有入口测试通过：手动 perRun、手动 seed source、seed 日志、预算摘要与默认不写 elite archive。没有宣称完整测试套件通过。
- 首个新增 JVM 已成功退出后，核查器因 Windows Java stdout 编码出现 `UnicodeDecodeError`。修正为严格 UTF-8/GB18030 解码并回读成功输出；该运行未重复启动。原始日志和生命周期记录保留。
- 入口未导出完整调度，本轮没有独立逐任务验算。Java 算法实现与默认配置未修改。
- 复用项来自八月批次，新项使用本轮冻结实现；源码状态、seed 来源和运行现场不同。时间列保留各自原口径，四槽并发与 BelowNormal 的新计时不用于公平速度排名；不报告基线优越性或显著性。
